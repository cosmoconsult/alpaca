# COSMO Alpaca Newsletter 09/2026

Welcome to this edition of the COSMO Alpaca Newsletter! Here's what's new and noteworthy.

---

## General

- **Container Origin Visualization and Grouping:** Containers are now by default grouped by their origin in the container tree (new setting `groupContainersByOrigin`). GitHub and Azure DevOps sections are shown when containers from both origins are present, while single-origin containers remain ungrouped when the active view matches their origin.

- **GitHub Verified Email Addresses:** Containers are now retrieved for a GitHub account using its verified email addresses in addition to the username. This makes containers created in the Azure DevOps context using a verified email address also visible in the GitHub view.

- **Deploy to Container:** Apps from NuGet feeds and Azure DevOps Artifacts can now be deployed directly from the VS Code extension to a container. Select a package or package version in the tree view and choose the container to which it should be deployed. When no version is selected, the latest available version will be deployed. [→ See Packages View actions for GitHub](https://docs.cosmoconsult.com/en-us/cloud-service/alpaca/github/packages-view.html#actions) | [→ See Packages View actions for Azure DevOps](https://docs.cosmoconsult.com/en-us/cloud-service/alpaca/azure-devops/packages-view.html#actions)

- **Validate NuGet artifacts before Container creation:** Container creation now validates configured NuGet artifacts before provisioning starts. Invalid or unavailable packages are reported early, so configuration problems can be identified before a container is created.

- **Warning for Containers older than one year:** Containers that are more than one year old now display a warning badge in the container tree. This helps identify stale environments and decide whether they can be deleted. It is recommended to work with short-lived containers, as older container images are not updated and do not receive security or image updates provided by Microsoft.

- **Automatic FileBrowser URL Conversion:** Artifact URLs that mistakenly point to a FileBrowser share page are now automatically converted to the corresponding direct download URL. This conveniently prevents download failures caused by incorrectly configured links.

---

## GitHub / AL-Go

- **Automatic README Updates:** A new workflow titled **COSMO Alpaca - Update README** was introduced to make the README files in the repository look cleaner and more standardized.
The README is updated with information about all the apps contained in the repository and their dependencies. The workflow has to be dispatched manually for now.

- **Improved Code Analysis:** It is now possible to define different code analyzers and rulesets and to validate object prefixes in test apps. [→ Read the docs](https://docs.cosmoconsult.com/en-us/cloud-service/alpaca/github/setup-al-go-settings.html#code-analyzers-for-test-apps). In addition, it is now possible to work with obsoleteTagVersion and different obsoleteTagPattern. [→ Read the docs](https://docs.cosmoconsult.com/en-us/cloud-service/alpaca/github/setup-al-go-settings.html#appsourcecop).

- **Update to AL-Go v9.2:** The custom AL-Go templates for COSMO Alpaca (**Alpaca-AppSource** and **Alpaca-PTE**) were updated from AL-Go v9.0 to v9.2.
  - Some highlights:
    - New setting `doNotPerformUpgrade` to skip publishing of previous app version in container
    - Conditional Settings now support conditions for workflow triggers/events
    - Support for workspace compilation _(currently not supported by COSMO Alpaca)_
    - Optimized Project Dependencies download (all project dependencies are downloaded before the build job)
    - Check out the release notes for [AL-Go v9.1](https://github.com/microsoft/AL-Go/releases/tag/v9.1) and [AL-Go v9.2](https://github.com/microsoft/AL-Go/releases/tag/v9.2) for more details.

- **Fixed Project Dependency Publishing:** Workflow artifact apps of project dependencies are now published in the container even if another version is already installed.

- **Fixed Test-App Dependency Downloads:** Missing dependencies for test apps are now downloaded for the correct Business Central version instead of always selecting the latest available package. This fix is included in BcContainerHelper 6.1.18. [→ See the AL-Go issue](https://github.com/microsoft/AL-Go/issues/2322) | [→ See the fix](https://github.com/microsoft/navcontainerhelper/pull/4175)

- **Create Containers for build modes:** When creating a development container for an AL-Go project, you can now select the build mode from the modes defined in the project's settings. The default mode is always available, and additional project-specific build modes are loaded dynamically, making it easier to create a container that matches a specific build configuration.
