# COSMO Alpaca Newsletter 07/2026

Welcome to the third edition of the COSMO Alpaca Newsletter! Here's what's new and noteworthy.

---

## General

- **Fixed issues with the next major version (BC29):** We fixed some issues that were caused by changes introduced with the next major version of Business Central (BC29).

- **Database Backup and Conversion:** The backup and conversion features from the legacy extension are now available in the new extension. You can create backups of your container's database and convert existing `.bacpac` backup files to `.bak` format directly from VS Code, streamlining your backup workflow without requiring external tools. [→ Read the docs](https://docs.cosmoconsult.com/en-us/cloud-service/alpaca/github/convert-bacpac-to-bak.html)

---

## GitHub / AL-Go

- **Update to AL-Go v9.0:** The custom AL-Go templates for COSMO Alpaca (**Alpaca-AppSource** and **Alpaca-PTE**) were updated from AL-Go v8.3 to v9.0. Check out the release notes for [AL-Go v9.0](https://github.com/microsoft/AL-Go/releases/tag/v9.0) for more details.

- **AAD Authentication Support for Dev Containers:** You can now configure authentication methods for GitHub development containers created via VS Code. Choose between NavUserPassword (traditional) or AAD authentication. When using AAD, a verified email address of your GitHub account that matches your tenant domain configured in the Alpaca backend is automatically resolved. [→ Read the docs](https://docs.cosmoconsult.com/en-us/cloud-service/alpaca/github/setup-al-go-settings.html#authentication)

- **Inherit App Dependencies to Artifacts:** App dependencies are now automatically detected from your `app.json` files and inherited as NuGet artifacts for container configuration. If all your app dependencies are available as NuGet artifacts within COSMO Alpaca (see [Packages View](https://docs.cosmoconsult.com/en-us/cloud-service/alpaca/github/packages-view.html)), manual artifact configuration becomes optional. Configured artifacts take precedence when conflicts occur. The feature fully supports the AL-Go setting `nugetFeedSelectMode` when resolving NuGet package versions.

- **Federated credentials:** You can now configure federated credentials for GitHub deployments; this is also the recommended approach. [→ Read the docs](https://docs.cosmoconsult.com/en-us/cloud-service/alpaca/github/add-environment.html)

- **Dropped support for Windows PowerShell:** To ensure the service continues to run smoothly, Windows PowerShell (v5) is no longer supported. It is now mandatory to run all jobs using PowerShell Core (v7). Our templates have been designed this way from the start.

- **Ensure Test Execution:** A new setting was added to ensure test execution. This is great to set at the Organization level to enforce tests for all projects. [→ Read the docs](https://docs.cosmoconsult.com/en-us/cloud-service/alpaca/github/setup-al-go-settings.html#tests)

- **ALCops Integration:** Now it's even easier to enable ALCops in AL-Go. [→ Read the docs](https://docs.cosmoconsult.com/en-us/cloud-service/alpaca/github/custom-codecops.html)

- **Improved logging of translation issues for build workflows:** The notes of the translation issues found by XLIFF Sync are now listed in the log and annotations.

---

## Azure DevOps

- **Dashboard Import:** Import dashboards from one Azure DevOps project to another with the new Import Dashboard feature in COSMO Alpaca. Widget queries are automatically remapped to the target project, and missing teams are created automatically. [→ Read the docs](https://docs.cosmoconsult.com/en-us/cloud-service/alpaca/azure-devops/import-dashboard.html)

- **Set up artifacts dependent on the test app:** Artifacts can now be set up as dependent on the test app (as for the app) using the parameter `dependsOn`. These artifacts are downloaded on container start but will only be installed by the pipeline after installing the test app. [→ Read the docs](https://docs.cosmoconsult.com/en-us/cloud-service/devops-docker-selfservice/azure-devops/setup-artifacts.html)

- **Build-by metadata in app manifests:** The build pipeline now sets the build-by metadata to "COSMO Alpaca v<version>" when compiling the app and test app.
